# Tag 3 — Git & GitHub: Versionskontrolle & Kollaboration

**Was gelernt?**
Wie Änderungen als Snapshots (Commits) gespeichert werden, wie ein Branch ein risikofreies Experimentierfeld neben dem Hauptstand ist, und wie ein Pull Request diese Änderungen kontrolliert wieder zusammenführt.

**Welches Problem?**
Bisher war meine einzige Form von "Versionskontrolle" ein Ordner voller Excel-Dateien mit Namen wie "final", "final2", "final_wirklich". Das genaue Gegenteil von nachvollziehbar.

**Wie gelöst?**
Dieses Repository selbst als Übungsfeld genutzt: ein Feature-Branch angelegt, Änderungen committet, Pull Request auf mich selbst erstellt und gemerged. Der Groschen ist gefallen, als ich gesehen habe, wie klar die Historie dadurch wird — genau das fehlt mir aktuell komplett bei den Excel-Tabellen im Betrieb.
